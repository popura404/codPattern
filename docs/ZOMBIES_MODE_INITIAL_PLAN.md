# 类 Hypixel 僵尸模式初版玩法方案

版本：草案 0.1

本文档只设计玩法与逻辑，不指定具体源码文件。后续实现时应接入当前通用模式框架，避免把僵尸模式写成 TDM 特例，也不要复用 TDM 的队伍比分或重生语义。开局前可以复用通用房间的准备和投票交互，但投票通过后的传送、倒计时、开波流程应由僵尸模式自己定义。

## 设计边界

- 目标是做“协作波次生存 + 编号屏障推进 + 购买成长”的玩法，不直接复刻 Hypixel 的地图、文案、素材、精确数值和完整波次表。
- 僵尸模式应是独立 PvE 协作模式，初版房间最多 4 名玩家，人数上限先硬编码。
- 初版优先保证一局能完整开始、推进波次、生成怪物、结算失败、清理实体。
- 所有经济、商店、编号屏障、窗口、波次和怪物规则都应属于僵尸模式自身，不进入公共模式层。
- 地图数据、对象点位和数值表要尽量数据化，方便以后调平衡。
- 初版暂不考虑无限波次，先以项目自定义的有限波次表驱动一局完整体验。

## 核心体验

玩家进入房间后先准备，房间成员可发起开局投票。投票通过后所有成员传送到起点，进入 20 秒开局倒计时；倒计时结束后再等待 10 秒，开始第一波。每一波会按当前波次、人数和已激活的编号僵尸复活点生成僵尸。玩家击中或击杀怪物获得点数，用点数购买武器、弹药、解除编号屏障、修复窗口、启动机关、购买装甲或购买强化。波次结束后进入短暂准备时间，所有仍存活玩家继续推进下一波。初版不做倒地救援；玩家死亡后播放 TDM 死亡动画表现，然后切换为观战状态。所有玩家都死亡观战或离开时，本局失败并清理房间。

初版不追求复杂剧情任务，先做一个可循环的生存框架。

## 对局阶段

| 阶段 | 说明 | 主要逻辑 |
|---|---|---|
| 等待/准备 | 玩家加入房间、选择背包或使用默认初始装备，并切换准备状态 | 最多 4 人，不生成怪物，不计分 |
| 开局投票 | 房间成员发起开始投票 | 只允许已加入成员投票，投票通过后锁定房间状态 |
| 开局倒计时 | 投票通过后传送玩家到起点，开始 20 秒倒计时 | 清理旧实体，发初始装备，不生成怪物，不计分 |
| 开波等待 | 20 秒倒计时结束后的 10 秒缓冲 | 玩家已在起点，可移动和购买允许的初始对象，不生成怪物 |
| 波次中 | 当前波次正在进行 | 按预算刷怪，处理奖励、死亡观战、对象交互 |
| 波间准备 | 一波结束后的短暂停顿 | 发放波次奖励，允许购买和解除屏障 |
| 失败 | 所有玩家死亡观战、离开或无存活玩家 | 停止刷怪，展示结果，清理实体 |
| 结束 | 返回大厅或结束点 | 清理玩家临时状态 |

建议初始参数：

```json
{
  "maxPlayers": 4,
  "maxPlayersHardcoded": true,
  "startVoteTimeoutSeconds": 15,
  "startVoteRequiresAllReady": true,
  "startVoteRequiredPercent": 60,
  "preGameCountdownSeconds": 20,
  "firstWaveDelaySeconds": 10,
  "intermissionSeconds": 18,
  "failDelaySeconds": 8,
  "friendlyFire": false,
  "lateJoinPolicy": "spectate",
  "deadPlayerPolicy": "spectate_until_match_end",
  "playerEconomyIndependent": true
}
```

开局准备与投票规则：

1. 初版房间最多 4 人，人数上限硬编码到僵尸模式定义或运行时校验中。
2. 等待/准备阶段允许已加入玩家切换准备状态。
3. 所有已加入玩家准备后，任意房间成员可以发起开始投票。
4. 开始投票只面向当前房间成员，投票超时或未达到通过阈值则保持等待/准备阶段。
5. 投票通过后立即锁定房间、清理旧实体、传送所有成员到起点并发放初始装备。
6. 传送完成后进入 20 秒开局倒计时；倒计时结束后进入 10 秒开波等待；等待结束后开始第一波。
7. 开局倒计时和开波等待期间不生成怪物，不发击杀或命中奖励。

## 玩家状态

每个玩家在房间内维护临时状态：

| 字段 | 用途 |
|---|---|
| points | 本局点数 |
| kills | 击杀数 |
| assists | 助攻数，可后续再做 |
| deaths | 死亡次数 |
| downs | 倒地次数，初版保留字段但不启用救援逻辑 |
| alive_state | 存活、死亡观战、离开 |
| perks | 已购买强化 |
| current_group | 当前所在编号区域或最近激活组，可用于提示和刷怪权重 |

初版死亡和观战逻辑：

1. 玩家受到致命伤害时允许触发死亡流程，不在初版拦截成倒地状态。
2. 死亡表现复用 TDM 的死亡动画或死亡镜头表现，但不复用 TDM 的队伍比分、重生发包或结算语义。
3. 死亡动画结束后玩家进入观战状态，不能攻击、购买或触发对象交互。
4. 初版死亡玩家不在下一波自动复活；波间复活、救援和自救都放到后续阶段。
5. 所有房间成员都处于死亡观战或离开状态时，房间进入失败。
6. 保留 `downs` 字段只作为后续倒地救援扩展预留，不参与初版失败判定。

## 波次逻辑

初版暂不做无限波次，波次由数据文件驱动，不把每波数值写死到代码里。配置格式统一使用 JSON，文档示例和实际落地都按同一种结构表达。

推荐把全局默认值、怪物类型表和每波配置拆开：

```text
serverconfig/codpattern/zombies_rules/
  config.json
  mobs.json
  weapons.json
  waves/
    wave_001.json
    wave_002.json
    wave_003.json
    wave_010_boss.json
```

全局配置负责默认值和房间规则，每波配置只写本波差异，缺失字段继承默认值：

```json
{
  "room": {
    "maxPlayers": 4,
    "preGameCountdownSeconds": 20,
    "firstWaveDelaySeconds": 10,
    "intermissionSeconds": 18,
    "failDelaySeconds": 8
  },
  "maxWave": 20,
  "defaults": {
    "healthMultiplier": 1.0,
    "damageMultiplier": 1.0,
    "speedMultiplier": 1.0,
    "maxAlive": 8,
    "spawnIntervalTicks": 40
  }
}
```

每波文件负责控制本波血量倍率、移动速度倍率、伤害倍率、同时存活上限、刷怪节奏、生成生物种类和数量：

```json
{
  "wave": 4,
  "healthMultiplier": 1.25,
  "damageMultiplier": 1.10,
  "speedMultiplier": 1.08,
  "maxAlive": 10,
  "spawnIntervalTicks": 35,
  "mobs": [
    { "type": "normal_zombie", "count": 18 },
    { "type": "fast_zombie", "count": 4 }
  ],
  "rewards": {
    "completionPoints": 60
  }
}
```

如果需要按玩家人数微调数量，可以在每波配置里增加可选字段，例如 `countPerPlayer` 或 `playerCountMultiplier`，由波次导演在开波时一次性计算本波预算。

刷怪循环：

1. 只从已激活的编号僵尸复活点生成。
2. 当前存活怪物数低于本波 `maxAlive` 时，按 `spawnIntervalTicks` 间隔尝试刷怪。
3. 每次生成后登记到当前房间，死亡、离场或结算时可准确统计和清理。
4. 本波预算用尽且房间内归属怪物为 0 时，进入波间准备。
5. 如果怪物长时间卡住、离玩家过远或所在区块不可用，触发回收或重刷。
6. 如果下一波配置不存在，房间进入胜利或结算阶段，而不是继续公式生成无限波次。

## 怪物设计

初版优先使用原版实体加属性、装备和模式专属 AI 目标控制，不先依赖复杂自定义实体。

| 类型 | 出现时机 | 作用 |
|---|---|---|
| 普通僵尸 | 第 1 波起 | 基础压力 |
| 快速僵尸 | 第 4 波起 | 追击落单玩家 |
| 装甲僵尸 | 第 6 波起 | 提高子弹消耗 |
| 爆炸/自爆单位 | 第 8 波后可选 | 逼迫玩家移动 |
| 精英怪 | 每 5 波或随机 | 小型目标 |
| Boss | 每 10 波或地图事件 | 阶段性检查玩家装备 |

僵尸模式怪物应使用房间级目标追踪服务，不依赖原版怪物视线发现玩家。怪物可以无视遮挡锁定本房间存活玩家；视线只影响攻击命中，不影响目标选择。移动仍使用原版寻路和碰撞规则，不做穿墙移动。

该追踪逻辑只作用于僵尸模式生成并登记到本房间的怪物，不修改全局原版怪物 AI。若怪物长时间无法接近目标，应由波次导演执行重新寻路、换目标、传送到合法刷怪点或回收重刷。

怪物属性不要写死到逻辑中，建议按怪物类型表和每波倍率计算。通用成长倍率可以作为默认值保留，但每一波应允许覆盖：

```json
{
  "zombieScaling": {
    "healthGrowthPerWave": 0.10,
    "damageGrowthPerWave": 0.04,
    "speedGrowthPerWave": 0.015,
    "maxSpeedBonus": 0.35
  }
}
```

## 经济与奖励

点数只在当前房间本局内有效，不持久化。玩家之间经济独立：每个玩家只拥有自己的点数、击杀、死亡观战、强化和购买状态，初版没有全队共享点数池。购买武器、补弹、装甲和强化只扣除购买者个人点数。编号屏障由交互玩家个人支付，解除结果对全队生效；后续如果开门压力过高，可以再扩展为均摊付款或队友捐点，但不作为初版规则。

首版奖励建议：

| 行为 | 初版奖励 | 评估 |
|---|---|---|
| 命中怪物 | 1 点 | 可以保留，但必须有单怪全局命中奖励上限，普通怪建议 10-15 点，精英和 Boss 单独配置 |
| 击杀怪物 | 10 点 | 数值合理，作为稳定主收入，不宜过高 |
| 助攻 | 3 点，后续可做 | 初版可以先关闭；开启后只给真实参与伤害的玩家，避免全队蹭助攻 |
| 爆头或弱点击杀 | 额外 2-5 点，可选 | 可以作为技术奖励，建议只在最终击杀时发放 |
| 修复窗口 | 每段 5 点，有冷却 | 数值合理，但同一窗口每波必须有上限 |
| 波次完成 | `25 + 当前波次 * 5`，全员独立发放，建议上限 150 | 用作低输出玩家的兜底收入，不能成为主要收入 |
| 救起队友 | 后续启用 | 初版不做倒地救援；后续上线时每次倒地事件只发一次，避免反复刷救援 |

首版经济目标不是让玩家每波都能买新东西，而是让平均玩家第 2-3 波可以买到低级墙枪，第 3-5 波能由一名玩家支付第一道编号屏障，第 5-7 波开始考虑稀有武器、装甲或第一次强化。波次怪物数量、命中奖励上限和物价应按这个节奏反推。

消费价格建议：

| 消费项 | 建议价格 | 评估 |
|---|---|---|
| 低级墙枪 / common | 500-700 | 当前 `500` 合理，适合作为第一把购买武器 |
| 中级墙枪 / rare | 900-1200 | 当前 `900` 合理，适合第 4 波后进入 |
| 高级墙枪 / epic | 1500-2200 | 当前 `1500` 偏友好，可先用作测试值 |
| 补弹 | 武器价格的 25%-40% | 原先 30%-50% 可行，但上限略高，容易让玩家买枪后没钱推进 |
| 第一组编号屏障 | 500-750 | 独立经济下不宜太高，否则付款玩家会明显落后 |
| 后续编号屏障 | 750、1000、1250 递增 | 用地图推进节奏控制压力，不建议每组都大幅跳价 |
| 装甲购买 | 400-600 | 应早于高阶强化开放，作为容错消费 |
| 装甲补充 | 150-300 | 价格低于重新购买，避免玩家因补甲过贵而放弃防御 |
| 武器强化 1/2/3 | 1200 / 2500 / 5000 | 和 `1.25 / 1.5 / 2.0` 倍率匹配，放到中后期 |

防刷限制：

- 每只怪物的命中奖励有全局上限，不按玩家分别累计上限。
- 同一窗口修复奖励有冷却或每波上限。
- 环境伤害、摔落和非玩家来源击杀默认不发完整奖励。
- 独立经济下不要把队友购买、队友击杀或队友修复的奖励发给全队。
- 离开房间或对局结束清空点数。

## 地图对象

地图对象应由编辑器数据描述，运行时只读取对象类型、坐标、编号和参数。初版暂不做复杂区域关系，先用编号屏障组驱动编号僵尸复活点组激活。

玩家出生点和僵尸复活点都按“点位”处理：保存维度、坐标和朝向，运行时从点位集合中选择合法位置。差异在于玩家出生点用于开局传送和后续复活扩展；僵尸复活点用于波次导演生成怪物，并额外带编号组和权重。MVP 1 至少要求地图包含玩家出生点和 `1` 号僵尸复活点组；`1` 号组开局默认激活，不依赖屏障。

| 对象 | 初版行为 |
|---|---|
| 玩家出生点 | 开局传送位置；后续做复活时也从这里或专用复活点选择 |
| 僵尸复活点 | 与玩家出生点类似的点位数据，额外绑定数字编号和权重；同号屏障解除后激活对应编号复活点组 |
| 编号屏障 | 花费点数交互解除；同号屏障任意一个被解除后，同号屏障全部消失 |
| 窗口 | 作为刷怪入口，可被破坏和修复 |
| 武器墙 | 由武器墙工具按等级部署；运行时从对应等级武器池随机分配武器，玩家购买该武器或补弹 |
| 弹药补给 | 给当前武器或背包补弹 |
| 装甲购买点 | 购买或补充装甲，初版不受编号区域限制 |
| 强化机 | 购买生命、速度、换弹等强化 |
| 电源开关 | 解锁强化机、机关和高级对象 |
| 神秘箱 | 后续做随机武器池，初版可暂缓 |
| 陷阱 | 后续做区域伤害和冷却，初版可暂缓 |

编号屏障和僵尸复活点推荐使用简单数字关系。示例统一按 JSON 表达：

```json
{
  "zombieSpawn": {
    "objectId": "zombie_spawn_2_a",
    "group": 2,
    "weight": 1.0,
    "dimension": "minecraft:overworld",
    "pos": { "x": 120, "y": 65, "z": -34 },
    "yaw": 90.0,
    "pitch": 0.0
  },
  "barrier": {
    "objectId": "barrier_2_a",
    "group": 2,
    "cost": 750,
    "blocksPlayersOnly": true,
    "dimension": "minecraft:overworld",
    "pos": { "x": 118, "y": 64, "z": -30 }
  }
}
```

开局默认激活 1 号僵尸复活点组。玩家与任意 `2` 号屏障交互并支付费用后，所有 `2` 号屏障消失，同时激活 `2` 号僵尸复活点组；`3`、`4`、`5` 号以此类推。

如果首版地图工具暂时只能编辑普通点位、不能给点位写复杂 payload，可以先用独立点位层表示编号，例如 `zombie_spawn_1`、`zombie_spawn_2`、`zombie_spawn_3`，权重默认 `1.0`。后续再升级为 repeatable object 或带 payload 的点位数据。

编号屏障初版只阻隔玩家，不阻隔怪物、投射物、掉落物或其它实体。因此它不应作为普通实心方块碰撞来实现，而应作为僵尸模式对象控制玩家通过和交互反馈。

墙购、装甲购买点和强化机初版不按编号区域限制启用；后续如果地图复杂度上升，再追加对象启用条件。

武器墙初版建议按等级部署，而不是在地图对象里直接写死具体武器。地图编辑工具提供武器墙放置功能，放置时选择等级，例如 `common`、`rare`、`epic`。房间开始或地图对象初始化时，运行时从该等级对应的配置武器池里按权重随机抽取具体 TaCZ 武器，并把抽取结果保存到本局对象状态中，保证同一局内该武器墙稳定可购买和补弹。后续如果需要制作固定教学图或特殊点位，可以给武器墙增加可选的 `fixedGunId` 覆盖字段。

```json
{
  "weaponWall": {
    "objectId": "weapon_wall_rare_01",
    "rarity": "rare",
    "priceOverride": null,
    "dimension": "minecraft:overworld",
    "pos": { "x": 130, "y": 65, "z": -42 }
  }
}
```

窗口初版可以简化：

```json
{
  "window": {
    "objectId": "window_01",
    "area": "lobby",
    "spawnPoint": "lobby_window_01",
    "maxBoards": 6,
    "repairPointsPerBoard": 5,
    "dimension": "minecraft:overworld",
    "pos": { "x": 124, "y": 65, "z": -38 }
  }
}
```

## 武器和背包

僵尸模式不要直接沿用 TDM 的重生发包逻辑，也不要把 TDM 的完整背包选择界面搬进来。背包系统可以作为公共入口存在，但不同模式应有自己的背包页面、配置和发放语义。

初版建议：

- 背包 GUI 顶部中间提供两个模式按钮：`团队竞技` 和 `僵尸生存`。
- 点击 `团队竞技` 保留现有 TDM 背包选择和配置逻辑。
- 点击 `僵尸生存` 打开僵尸模式专用简化页面。
- 僵尸生存页面不显示背包列表，不支持多个背包选择，不显示 LR 战术/杀伤手雷栏。
- 僵尸生存页面只显示一个初始武器槽，用于选择本局开局武器。
- 僵尸初始武器槽使用独立的筛选配置，结构可以参考 TDM 的 `weapon_filter.json`，但不要复用 TDM 的主武器、副武器、投掷物语义。
- 僵尸初始武器筛选默认只开放 `pistol` 和 `melee`，推荐默认值为手枪；如果 LR Tactical 未加载或没有近战数据，则 `melee` 分类为空或隐藏。
- 武器墙按等级从配置武器池随机分配具体 TaCZ 武器。
- 弹药购买按武器类型或当前手持武器计算价格。
- 同一把 TaCZ 武器可以出现在不同等级池中，由等级决定本局基础伤害倍率和价格层级。
- 局内强化机后续可以在武器实例上叠加强化倍率，最终倍率按“等级倍率 * 强化倍率”计算。
- 高级配件、特殊弹药放到后续阶段。

推荐新增僵尸背包配置，而不是改造 TDM 玩家背包数据：

```text
serverconfig/codpattern/backpack_rules/
  backpack_config.json
  weapon_filter.json
  zombies_backpack_config.json
  zombies_weapon_filter.json
```

`zombies_backpack_config.json` 只保存每个玩家的僵尸初始武器槽：

```json
{
  "playerData": {
    "<player-uuid>": {
      "weapon": {
        "item": "tacz:modern_kinetic_gun",
        "count": 1,
        "nbt": "{GunId:\"tacz:glock_17\",GunCurrentAmmoCount:17,GunFireMode:\"SEMI\",HasBulletInBarrel:1}"
      }
    }
  }
}
```

`zombies_weapon_filter.json` 只描述单槽可选武器分类和黑名单：

```json
{
  "weaponTabs": ["pistol", "melee"],
  "defaultWeapon": {
    "item": "tacz:modern_kinetic_gun",
    "count": 1,
    "nbt": "{GunId:\"tacz:glock_17\",GunCurrentAmmoCount:17,GunFireMode:\"SEMI\",HasBulletInBarrel:1}"
  },
  "blockedItemNamespaces": ["example_gunpack"],
  "blockedWeaponIds": ["namespace:gunid"],
  "blockedAttachmentNamespaces": ["example_attachment_pack"],
  "blockedAttachmentIds": ["namespace:attachmentid"]
}
```

僵尸模式开局发放只读取 `zombies_backpack_config.json` 的 `weapon` 槽。发放时清空普通背包带入的战斗物品，只给初始武器和必要弹药，不发 TDM 的副武器、战术投掷物、杀伤投掷物和配装补给。这样可以保证玩家开局强度可控，后续主要成长仍由墙购、补弹、装甲和强化机承担。

实现上建议复用现有背包系统的基础能力，例如 ItemStack 构建、TaCZ/LR Tactical 分类读取、黑名单过滤和武器选择按钮；但僵尸专用数据模型、保存路径、更新 packet、发放服务和 GUI 页面应独立命名。不要把僵尸单槽硬塞进 TDM 的 `primary/secondary/tactical/lethal` 四槽逻辑，否则后续容易出现 TDM 背包影响僵尸开局、僵尸配置污染 TDM 发包的问题。

武器配置建议独立为 `weapons.json`，按等级维护武器池、价格和基础伤害倍率：

```json
{
  "rarities": {
    "common": {
      "damageMultiplier": 1.0,
      "price": 500,
      "weapons": [
        { "gunId": "tacz:glock_17", "weight": 5 },
        { "gunId": "tacz:p320", "weight": 4 }
      ]
    },
    "rare": {
      "damageMultiplier": 1.25,
      "price": 900,
      "weapons": [
        { "gunId": "tacz:m4a1", "weight": 3 },
        { "gunId": "tacz:ak47", "weight": 3 }
      ]
    },
    "epic": {
      "damageMultiplier": 1.5,
      "price": 1500,
      "weapons": [
        { "gunId": "tacz:hk_g3", "weight": 2 }
      ]
    }
  },
  "upgradeMultipliers": {
    "0": 1.0,
    "1": 1.25,
    "2": 1.5,
    "3": 2.0
  }
}
```

购买武器时，服务端应把僵尸模式专用字段写到武器 ItemStack 或等价的实例状态中，例如等级、等级倍率、强化等级和强化倍率。TaCZ 命中事件里只按本房间、僵尸模式武器和僵尸模式怪物生效，读取实例倍率后修改本次枪械伤害。不要直接修改 TaCZ 全局伤害配置，否则会影响 TDM、普通生存和其它模式。

建议武器价格先分层：

| 层级 | 价格范围 | 例子 |
|---|---|---|
| 初始 | 免费 | 手枪、近战 |
| 低级墙枪 | 500-900 | 冲锋枪、霰弹枪 |
| 中级墙枪 | 1000-1800 | 步枪、轻机枪 |
| 高级随机池 | 950/次或更高 | 后续神秘箱 |
| 补弹 | 武器价格的 25%-40% | 当前武器补弹 |

## HUD 与提示

初版 HUD 先做清晰可用，不追求完整美术包装。HUD 数据通过僵尸模式自己的运行态快照同步，不复用 TDM 的比分、阶段 packet 或 `ClientTdmState`。如果需要复用 TDM 的死亡动画表现，只复用展示效果，不让 HUD 依赖 TDM 房间语义。

局内 HUD 至少展示：

- 当前波次。
- 剩余怪物数。
- 当前点数。
- 当前阶段和倒计时。
- 队友存活、死亡观战或离开状态。
- 交互对象提示，例如费用、条件不足、电源未开启。

初版布局建议：

| 区域 | 内容 | 说明 |
|---|---|---|
| 顶部居中 | 阶段名和倒计时 | 开局倒计时、开波等待、波间准备、失败倒计时都放这里 |
| 左上 | 当前波次、剩余怪物数 | `WAVE 4`、`剩余 12` 这类高频信息 |
| 左下或经验条上方 | 当前个人点数 | 点数只显示本玩家自己的经济，不显示全队总额 |
| 右侧 | 队友状态列表 | 最多 4 人，显示存活、死亡观战、离开；初版不显示倒地救援进度 |
| 准星附近 | 交互提示 | 武器墙价格、屏障价格、补弹、条件不足、电源未开启 |
| 屏幕中央短提示 | 波次开始、波次完成、失败 | 使用短暂淡入淡出提示，不遮挡主要视野 |

运行态快照建议使用通用 key/value，避免在公共 packet 顶层加入僵尸专属字段：

```json
{
  "phaseKey": "WAVE_ACTIVE",
  "remainingTimeTicks": 0,
  "metrics": [
    { "key": "wave", "labelKey": "hud.codpattern.zombies.wave", "value": "4" },
    { "key": "zombies_left", "labelKey": "hud.codpattern.zombies.left", "value": "12" },
    { "key": "alive_players", "labelKey": "hud.codpattern.zombies.alive", "value": "2/4" }
  ],
  "playerValues": {
    "points": { "type": "int", "value": 640 },
    "kills": { "type": "int", "value": 18 },
    "alive_state": { "type": "string", "value": "ALIVE" }
  },
  "prompts": [
    { "key": "weapon_wall", "textKey": "hud.codpattern.zombies.buy_weapon", "priority": 10 }
  ]
}
```

HUD 初版验收：

- 非僵尸模式不显示僵尸 HUD。
- 玩家离房、断线或对局结束后清空 HUD 状态。
- 观战玩家仍能看到波次、剩余怪物和队友状态，但不能看到可购买交互提示。
- 交互提示以服务端校验结果为准，客户端只负责展示。

房间列表或房间详情建议展示：

- 模式名。
- 当前阶段。
- 当前波次。
- 玩家数。
- 存活人数。
- 剩余怪物数。

## 初版里程碑

### MVP 1：能玩一局

- 创建僵尸模式房间。
- 地图最少包含玩家出生点和 `1` 号僵尸复活点组；两者都按点位保存坐标和朝向。
- 房间成员准备并发起开始投票。
- 投票通过后传送玩家，按僵尸单槽背包配置发初始武器。
- 完成 20 秒开局倒计时和 10 秒开波等待。
- 开局默认激活 `1` 号僵尸复活点组，并只从已激活复活点按波次生成普通僵尸。
- 击杀给点数。
- 一波结束进入下一波。
- 玩家死亡后播放 TDM 死亡动画表现，然后进入观战状态。
- 所有玩家死亡观战或离开后失败。
- 初版 HUD 展示波次、剩余怪物数、个人点数、阶段倒计时和队友状态。
- 结束时清理本房间怪物和玩家状态。

### MVP 2：地图推进

- 增加 `2` 号及后续编号僵尸复活点组、编号屏障和窗口。
- 继续只从已激活编号复活点刷怪。
- 编号屏障可购买解除，同号屏障一次性全部消失，并激活同号复活点组。
- 窗口可破坏和修复。
- HUD 展示对象提示和购买失败原因。

### MVP 3：成长与变化

- 背包系统增加 `团队竞技` / `僵尸生存` 模式切换入口。
- 增加僵尸生存单槽初始武器 GUI 和独立武器筛选配置。
- 增加武器墙工具，支持按等级部署武器墙。
- 增加按等级分类的武器池，房间开始时为武器墙随机分配具体武器。
- 增加武器墙购买和补弹。
- 增加强化机和武器强化倍率。
- 增加快速、装甲、精英怪。
- 支持死亡玩家或中途加入玩家在波间复活。

### MVP 4：内容扩展

- 倒地救援和救起奖励。
- 神秘箱。
- 电源系统。
- 陷阱。
- Boss 波。
- 地图目标或撤离结局。
- 更细的武器池、配件和难度配置。

## 关键边界情况

- 玩家中途离开：本波预算不回退，下一波按剩余玩家重新计算。
- 所有玩家离开：立即结束房间并清理实体。
- 玩家死亡：播放 TDM 死亡动画表现后进入观战状态；初版不自动复活。
- 中途加入：初版默认观战，不参与当前对局；后续可扩展为波间复活。
- 怪物卡住或寻路失败：超过时间未接近目标则重新寻路、换目标、传送到合法刷怪点或回收。
- 区块未加载：不在未加载复活点刷怪；已存在怪物需要定期清理无效引用。
- 地图对象缺失：如果缺少玩家出生点或 `1` 号僵尸复活点组，房间不能开始，并给出缺失项提示。
- 商店重复交互：服务端扣费和发货必须原子化，防止连点重复购买。
- 僵尸背包隔离：僵尸开局只读取僵尸单槽配置，不能读取或发放 TDM 的完整背包。
- 玩家经济独立：点数、购买状态和奖励发放不能串到队友身上；全队受益对象也只扣交互玩家个人点数。
- 武器墙随机分配：抽取结果应保存到本局对象状态中，同一局内不能每次交互重新随机。
- 伤害倍率范围：只对僵尸模式房间内的僵尸模式武器命中本房间怪物生效，不能污染其它模式或全局 TaCZ 配置。
- 结算清理：实体、点数、死亡观战状态、对象状态、HUD 状态都必须清空。

## 待确认问题

- 僵尸生存初始武器是否只允许 `pistol` 和 `melee`，还是后续开放更多低级分类。

- 武器强化机是否只强化当前手持武器，还是支持背包内全部僵尸模式武器。
- 第一张测试地图 MVP 1 最小对象：玩家出生点、`1` 号僵尸复活点组即可；MVP 2 再补 `2-3` 组僵尸复活点、`2` 组编号屏障、`4` 个窗口、`2` 个武器墙、`1` 个装甲购买点。

## 初版验收标准

- 不需要 TDM 假队伍和假比分也能显示房间和进入游戏。
- 房间开始后只影响本房间玩家和本房间怪物。
- 击杀、波次推进、点数、失败和清理逻辑稳定。
- 玩家之间经济独立，个人点数、奖励、购买和强化状态不会串账。
- 地图对象状态可同步给客户端，玩家看到明确交互反馈。
- 对局结束后没有残留怪物、残留 HUD、残留玩家点数或残留对象状态。
