# COD Pattern Q&A

[项目概览](README.md) | [详细 Guide](GUIDE.md) | [更新日志](CHANGES.md)

> 本文对应 `0.8.6b`。这里只收录常见问题和排查方向，完整配置、建图和迁移流程见 [Guide](GUIDE.md)。文中的 `serverconfig/` 均位于当前世界存档内。

## 1. 需要装哪些前置，为什么启动时提示缺少模组

主模组面向 Minecraft `1.20.1`、Forge `47.x`，需要 TaCZ `1.1.6` 或更高版本。客户端和服务端都要安装主模组及其必要依赖，并使用相互兼容的版本。

这几个模组需要分清：

- **FPSMatch**：相关核心已经内置，不再作为前置安装。
- **LR Tactical**：可选；安装时要求 `0.3.0` 或更高版本。未安装时不提供对应刀具和投掷物能力。
- **TaCZAddon（`taczaddon`）**：可选，用于补充改枪配件候选和兼容其配件处理逻辑。
- **COD Pattern Zombies（`codpattern_zombies`）**：独立附属。主模组可单独运行；安装该附属时，主模组声明的兼容下限为 `0.2.0b`。

启动失败时先查看 Forge 的缺失依赖提示和服务端日志，确认具体模组 ID、版本要求与报错位置。仅凭“打不开”无法判断是依赖、配置还是其他模组冲突。

## 2. 为什么模式列表里没有 Zombies

主模组只内置 `frontline` 和 `teamdeathmatch`。Zombies 由独立附属注册；只安装主模组时，不会出现僵尸模式和附属部署工具。

先检查客户端与服务端是否都已安装配套的 Zombies 附属，再查看服务端是否成功加载该模式。附属的依赖、玩法规则和部署流程以其对应版本说明为准。

## 3. 为什么找不到旧的建图、出生点命令

`0.8.6b` 的地图创建与点位编辑以工具为入口，旧的 `/cdp map create`、`/cdp map spawn` 等命令已不再提供。

当前入口：

- `frontline`／`teamdeathmatch`：使用地图创建工具创建地图。
- 出生点与区域：使用出生点工具，按所选模式显示可编辑内容。
- 地图列表、改名、结束位置、强制结算和删除：使用地图管理工具。
- Zombies：使用附属提供的部署工具。

三种主模组工具都在创造模式的「codpattern工具与物品」物品栏内。工具操作需要管理员权限；具体操作见 [Guide](GUIDE.md)。

## 4. 玩家重生后为什么没有拿到背包

先确认玩家已经在房间或对局中，且当前不是旁观者。自动发放有房间检查，旁观者即使使用强制发放也不会领取装备。

再检查：

1. 玩家是否有可用背包。所选 ID 不存在时会尝试使用已有背包中 ID 最小的一套。
2. 枪械及枪包是否已正确加载，背包内的物品 ID、NBT 是否有效。
3. 该枪是否被 `weapon_filter.json` 中的筛选规则或黑名单拦截。
4. 服务端日志是否出现物品 ID 无效、找不到物品或无法构建装备的提示。

管理员可用下列命令强制发放当前背包，需权限等级 `2`：

```mcfunction
/cdp distribute <玩家>
```

**发放背包会清空并重新填充玩家物品栏，同时重置专用投掷物槽。** 排查时先处理好玩家需要保留的物品。

## 5. 为什么投掷物不在快捷栏，按键也没有反应

战术和致命投掷物分别放在专用的「投1」「投2」槽中，不会作为普通背包装备填入快捷栏。

先检查三项：

1. 已安装兼容的 LR Tactical。
2. `weapon_filter.json` 中已启用 `throwablesEnabled`，背包内也已选择有效投掷物。
3. 在游戏「控制」设置中，为 COD Pattern 的两个投掷物槽分别绑定按键；默认都未绑定。

绑定后在房间内按住对应按键进入使用动作，达到投掷物的准备时间后松开触发投掷；过早松开或使用滚轮会取消动作。没有安装 LR Tactical 时，专用槽不会发放对应投掷物。

## 6. 为什么改了 `weapon_filter.json`，玩家界面没更新

保存当前存档中的文件后，由管理员执行：

```mcfunction
/cdp update
```

文件位置为：

```text
serverconfig/codpattern/backpack_rules/weapon_filter.json
```

此命令需要权限等级 `2`，会重新读取武器筛选配置，并向在线玩家同步筛选配置和当前背包数据。它不是所有配置文件的热重载命令，也不会立即给玩家重新发放装备。

## 7. 为什么手改背包或对局规则后没有生效

这两类文件不能直接套用上一问的做法：

- `serverconfig/codpattern/backpack_rules/backpack_config.json`：背包仓库会保留服务端缓存，在线手改可能被后续保存覆盖。需要手工修改时，先停服、备份，再编辑并重新启动。
- `serverconfig/codpattern/maps/builtin/rules/config.json`：内置团队竞技规则在服务端启动时加载，没有对应的在线热重载命令。

日常修改背包优先使用游戏内界面。修改磁盘配置前，先确认正在编辑的是当前世界存档内的文件。

## 8. 为什么 TaCZ 原生改枪界面会跳到背包界面

这是当前版本的设计。直接打开 TaCZ 原生改枪界面时，会转到 COD Pattern 背包界面；请将鼠标移到主武器或副武器卡片上，点击出现的「更换配件」按钮。直接点击武器卡片会进入更换武器列表。

这套流程由服务端建立改枪会话，检查可用配件和黑名单，并把保存结果写回对应背包槽位。旁观者不能开始改枪。

按 `Esc` 返回或正常关闭改枪界面会自动提交保存，当前没有单独的取消按钮。退出界面不会撤销刚才的改装。

## 9. 改枪配件太少，必须安装 TaCZAddon 吗

不必。没有 TaCZAddon 时，改枪仍可使用玩家物品栏中已有、适用于当前枪械且未被禁用的配件。

安装 TaCZAddon 后，会额外收集它提供的兼容配件候选，再经过适配检查、去重与黑名单过滤。候选数量仍受当前枪械、枪包和服务端规则影响。

已保存的配件预设和枪械 NBT 由主模组读取，不以 TaCZAddon 为前提。如果原有配件没有显示，先检查当前编辑的背包与武器槽是否正确、配件资源是否仍存在、配件是否被禁用，不要直接把原因归为“少装了 TaCZAddon”。

## 10. 配件保存失败通常是因为什么

按游戏内提示逐项检查：

1. 改枪会话是否仍然有效；超时阈值为 `120` 秒，服务端在后续 tick 检查并中止。
2. 保存时的背包 ID 和槽位，是否与开始改枪时一致。
3. 改枪会话里的物品是否仍是有效枪械。
4. 对应背包是否仍存在。
5. 枪上是否装了服务端黑名单中的配件。

正常结束会话会恢复改枪前的物品栏；保存被拒绝时不会把失败的配件变更作为新预设保留。出现超时或会话失效提示后，重新从对应背包槽位进入改枪。

## 11. 为什么新增背包后没有自动切过去

新增背包会尽量保留原来的选择，不会强制切到新背包。需要使用新背包时，在界面里手动选中它。

## 12. 房间列表里为什么没有我的地图

先确认模式是否已加载，再确认地图是否已经注册。管理员可执行：

```mcfunction
/cdp map list
/cdp map list frontline
/cdp map list teamdeathmatch
```

也可以打开地图管理工具，按模式查看当前注册的地图。

内置地图定义应保存在：

```text
serverconfig/codpattern/maps/builtin/frontline/<地图目录>/map.json
serverconfig/codpattern/maps/builtin/teamdeathmatch/<地图目录>/map.json
```

`<地图目录>` 使用 `m-` 加地图名 UTF-8 字节的十六进制编码，不一定能直接看到原地图名。请结合 `map.json` 内容确认，不要只按文件夹名称判断。

如果文件存在但列表中没有，查看启动日志中的地图加载错误；如果地图仍在旧 `fpsmatch/` 目录中，按第 19 问迁移。未加载对应附属、迁移未完成、地图处于删除流程或存储需要恢复时，也应先处理对应提示。

## 13. 为什么比赛进行中不能加入，或准备、开始按钮不可用

内置两种团队竞技模式只允许新玩家在 `WAITING` 阶段加入，不能在进行中的比赛里直接补入或自动转为旁观。

发起开始投票还需满足：

- 房间处于等待阶段，没有其他投票正在进行。
- 参赛人数达到规则中的最低人数。
- 所有参赛玩家均已准备。
- 地图已配置结束传送点 `endtp`。

投票有 `15` 秒时限，通过票数由服务端规则中的比例决定。准备状态也受比赛阶段限制；地图正在删除、迁移或恢复时，相关操作会额外被锁定。先根据界面提示处理阻塞原因。

## 14. 为什么死亡后一直处于旁观状态

先检查复活点是否可用。`teamdeathmatch` 在死亡后优先尝试动态候选点，失败后回退到初始出生点；`frontline` 使用初始出生点。点位应位于正确维度，并留出玩家站立空间；墙体、半砖和低矮天花板都可能影响落点碰撞检查。

管理员可使用出生点工具检查点位类型和位置，必要时补充可用点。动态候选点可通过工具的合并功能，将双方已有候选点合并后写回双方。

自动复活连续失败 `5` 次后会停止重试，并清除死亡黑屏、给出提示；玩家仍可能保持旁观状态。此时应先修复地图点位，再由管理员处理当前房间或重新组织对局，不能仅等待自动重试。

## 15. 比赛结束后为什么没有自动传回

先检查该地图的结束传送点是否已保存、目标维度是否可用、落点是否有足够空间。开始投票检查的是是否配置了结束点，实际传送仍可能因落点不可用而失败。

可在地图管理页选中地图，查看并修改单图的「结束传送」；或由权限等级 `3` 的管理员执行：

```mcfunction
/cdp map endtp show <地图名>
/cdp map endtp set
```

`set` 使用命令执行位置、所在维度和朝向，覆盖**所有已加载且支持结束传送的地图**。它不带地图名，不是单图设置命令。

如果不同模式有同名地图，`show` 会提示名称歧义。此时在地图管理页按模式选择即可；也可以在符合改名条件后为地图改名。

## 16. 为什么改了全局结束位置，已有地图没有变化

全局结束位置是**新建地图的默认值**，保存在：

```text
serverconfig/codpattern/maps/defaults.json
```

已有地图保留自己的结束位置。单图页面中的「使用全局位置」只是把当前默认值填入草稿，点击保存后才生效，之后也不会随着全局值变化。

需要一次覆盖已有地图时，使用上一问的 `/cdp map endtp set`；需要只修改一张地图时，使用地图管理页。

## 17. 地图为什么不能改名，提示“等待恢复”怎么办

改名要求地图空闲、没有参赛成员或观战者，也没有待恢复任务。名称不能为空，最多 `100` 个 UTF-8 字节，不能包含控制字符，同一模式下不能重名。

先刷新地图详情，查看占用情况、在线与离线待恢复人数和禁用原因。正在比赛的地图可由管理员强制结算，再等待玩家恢复和模式资源清理完成。

“等待恢复”不等于单纯的界面没刷新。离线玩家可能要上线后才能恢复；如果提示存储不可用或地图管理操作待恢复，保留 `.storage/` 及相关日志，按提示检查文件并重启，不要通过删除恢复记录来绕过限制。

## 18. 删除地图会拆掉建筑吗，为什么删除后还显示处理中

不会。删除针对地图定义和已注册的地图数据，世界方块保留。

有成员或正在比赛的地图，会先结束对局、恢复玩家并移出成员和观战者，完成必要清理后再归档地图数据。界面显示“等待恢复”时，删除尚未完成；刷新详情可查看进度和原因。删除失败时，先处理页面提示的问题，再按提示重试或重新确认。

地图管理页支持在允许的阶段取消删除。取消仅撤回后续删除意图，已经结束的比赛和已移出的玩家不会回到原来状态，必要恢复仍会继续。

已删除数据归档在：

```text
serverconfig/codpattern/maps/.storage/trash/
```

当前没有面向玩家的“一键还原地图”命令。误删后先停服保留完整存档和归档记录，优先恢复操作前备份。系统对中断操作的恢复与用户主动撤销已经完成的删除，是两件不同的事。

## 19. 旧地图怎么迁移，为什么升级后提示存储被锁定

本版本从当前世界存档的 `serverconfig/codpattern/maps/` 读取地图与规则，不会自动搬迁旧文件。旧 `fpsmatch/` 目录和旧规则路径中的数据，需要管理员手动检查、确认迁移。

处理顺序：

1. 备份完整世界存档与游戏目录下的 `fpsmatch/`，保留对应版本的主模组和附属。
2. 安装需要参与迁移的配套附属，结束受影响模式的比赛并让成员离开。
3. 使用权限等级 `4` 执行只读检查，核对源路径、目标路径和问题报告。
4. 确认备份与清单后再执行迁移。
5. 重启服务器，逐项检查地图、出生点、规则和附属功能。

```mcfunction
/cdp map migrate check
/cdp map migrate confirm
```

**`confirm` 会搬迁文件，成功迁移的旧文件会被移除。** 它只负责位置迁移，不保证旧数据与当前版本兼容。迁移后受影响模式会锁定到重启；部分失败时按报告修复后再检查，不要直接删除旧目录、迁移标记或备份。

## 20. 搬迁服务器时应该复制哪些数据

至少保留完整世界存档，包括背包配置、地图、规则、记录和 `serverconfig/codpattern/maps/.storage/` 中的迁移、归档及恢复数据。

同时保留游戏目录下的 `fpsmatch/`：其中可能仍有待迁移数据、其他模组数据，以及 `fpsmatch/.codpattern-migrations/` 中按存档记录的迁移标记。不要因为地图已经迁移，就整目录删除它。

已有 `migration.json` 的世界还受绝对路径限制：把世界搬到新路径后，可能出现 `Invalid or relocated migration journal`，地图随之被阻止加载或使用。`check`／`confirm` 不会自动把旧路径记录改成新路径。备份时应记录原目录，恢复时优先保持原绝对路径及配套的 `fpsmatch/`；不要删除迁移记录来绕过检查。

在新环境使用配套版本的主模组、附属和枪包，先确认上述路径条件，再检查服务端日志及地图列表。完整路径和迁移注意事项见 [Guide](GUIDE.md)。
